# Zenzai レイテンシ分析レポート

セッション数: 102

## 結論から言うと

**「Zenzai が遅い」という感覚は正しい。数字が裏付けている。**

fetch p50（変換処理の中央値）が 95.9ms、fetch_complete p50（体感レイテンシの中央値）が 195.2ms あり、全セッションの 23.5%（102件中24件）で fetch_complete p95 が 300ms を超えている。スキルの判定基準（> 20%）を上回っているため、Zenzai の外れ値が原因の可能性が高いとみてよい。

---

## 数字の読み方

### レイテンシの全体像

| 指標 | 中央値 | 最大値 |
|------|--------|--------|
| fetch p50 | 95.9ms | 375.5ms |
| fetch p95 | 151.0ms | 375.5ms |
| fetch_complete p50 | 195.2ms | 461.7ms |
| fetch_complete p95 | 237.7ms | 524.8ms |
| debounce 設定 | 70.0ms | 110.0ms |
| 打鍵間隔 p50 | 104.7ms | 380.8ms |

`fetch_complete - fetch` の差（≈実効 debounce 待ち）の中央値は 104.6ms、最大 207.4ms。debounce 設定（中央値 70ms）より大きく、非同期パイプラインのオーバーヘッドも乗っている。

### ワースト5セッション

fetch_complete p95 の上位を見ると、fetch p95 も同様に高い（291〜376ms）。debounce だけでは説明できず、変換処理そのものが遅い。これは Zenzai 推論の外れ値と見るのが自然。

### キャッシュ状況

ミス率が 50.1% と高い。読み長別では 2文字で 93.5%、3文字で 53.6% のミス率。2文字ミス率が高い点は旧ビルドの leftSideContext キー問題の可能性があるが、2026-06 以降のビルドでは修正済みのはず。修正後も高い場合はキャッシュ eviction（上限 50件）が頻繁に起きている可能性がある。

いずれにせよ、キャッシュミスが多いと Zenzai の実推論が走る回数が増えるため、レイテンシの外れ値が出やすくなる。

## ログから言えること・言えないこと

### 言えること

- fetch（変換処理時間）の p95 が 300ms 超のセッションが全体の 23.5% あり、Zenzai 推論の外れ値が存在する
- キャッシュミス率が 50% と高く、実推論の頻度が多い
- 2文字読みのミス率（93.5%）が突出しており、短い読みでキャッシュが効きにくい
- 打鍵間隔の中央値（104.7ms）に対して debounce 設定（70ms）は概ね適切な範囲

### 言えないこと

- Zenzai 推論単体の時間（fetch には AzooKey 変換も含まれる）
- Zenzai ON/OFF での比較（ログに Zenzai 有効フラグが含まれていない）
- 特定の読み長で Zenzai が遅い、といった傾向（fetch_p95_by_reading_len がスクリプト出力に現れなかったため、セッション内サンプルが少なすぎる可能性がある）

## 次のアクション

1. キャッシュ eviction の確認：2文字ミス率 93.5% が修正済みビルドでも続くなら、AzooKeyConverter.swift の LRU 上限（50件）を見直す。変換パターンが多様なユーザーでは 50 件で足りない可能性がある。

2. Zenzai 単体の時間を計測する仕組みを追加：fetch には AzooKey と Zenzai が混在している。Zenzai ON/OFF セッションを区別できるようにログに zenzai_enabled フラグを足すか、Zenzai 推論時間を別フィールドで記録すると原因を切り分けやすくなる。

3. セッション数が少ない点に注意：候補選択行動（1位確定率）は n=1 のみで信頼できる数値が出ていない。変換精度の評価は今後のセッション蓄積を待つ。

## 要約

「Zenzai 遅い気がする」という感覚は数字で支持されている。fetch_complete p95 が 300ms を超えるセッションが 23.5%（スキルの閾値 20% 超え）あり、その際の fetch p95 も同様に高い。キャッシュミスが多い（特に 2文字）ため Zenzai の実推論が頻繁に走っていることも遠因になっている。ただし「Zenzai のせいか AzooKey のせいか」をログ単体で断言するのは難しく、Zenzai 単体の計測フィールドを追加することが根本的な原因特定への近道。
