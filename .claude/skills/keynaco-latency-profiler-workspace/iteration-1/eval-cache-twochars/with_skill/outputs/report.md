# キャッシュ分析レポート（2文字読みの挙動）

分析日: 2026-06-17  
セッション数: 102

---

## まとめ

キャッシュ全体では「ほぼ機能していない」状態。ミスが 50.1% に達しており、特に 2 文字読みは 93.5% がキャッシュミスになっている。体感レイテンシ（`fetch_complete p95`）が 300ms 超のセッションが 23.5% あり、Zenzai 推論の外れ値が主因と見られる。

---

## キャッシュの状況

```
exact  :    87 件 (  6.5%)
prefix :   578 件 ( 43.4%)
miss   :   668 件 ( 50.1%)
```

overall のミス率は半数。`prefix`（短い読みのキャッシュを暫定表示に流用）が 43% と多く、「そこそこ応答は早いが正確なキャッシュには当たっていない」状態になっている。

### 読み長別ミス率

| 読み長 | ミス率 |
|--------|--------|
| 2 文字 | **93.5%** |
| 3 文字 | 53.6% |
| 4 文字 | 20.1% |
| 5 文字以上 | 4.9% |

2 文字の 93.5% は突出して高い。3 文字以降は読みが長くなるほど急速に改善しており、構造的な問題が 2 文字に集中している。

### 2 文字ミス率が高い原因

スキルのドキュメントによると、2 文字以下の読みは `leftSideContext` をキャッシュキーから除外するよう 2026-06 以降のビルドで修正済み。ただし今回の数値は 93.5% と依然高い。考えられる原因は以下の 2 点。

1. **修正前のビルドを使っている** — 2026-06 以前のビルドが残っている場合、`leftSideContext` がキャッシュキーに入ったままなので毎回ミスになる
2. **キャッシュ eviction（上限 50 件）** — 2 文字の入力は打鍵途中で頻出するが、キャッシュが 50 件上限を超えると oldest から追い出される。実際に修正済みのビルドでも 2 文字読みが次々と追い出されている可能性がある

現在のビルドが修正済みかどうかを確認し、古いままなら `/deploy` でビルド＆インストールを推奨する。


`fetch_complete - fetch ≈ 104.6ms`（中央値）。debounce 設定の 70ms より実効待ち時間が約 35ms 大きく、非同期パイプラインのオーバーヘッドが上乗せされている。

打鍵間隔（104.7ms）と debounce 設定（70ms）の差はわずか 35ms。速打ちのセッションでは debounce が毎打鍵発動している可能性がある。

`fetch_complete_p95 ≥ 300ms` のセッションが **102 件中 24 件（23.5%）** あり、スキルの要注意ライン（> 20%）を超えている。ワースト例：

fetch_p95 自体が 300ms 台に達しているため、Zenzai 推論の外れ値が主因と考えられる。
