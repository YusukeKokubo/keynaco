# keynaco ドキュメント整合性監査

## 原則

`docs/retrospectives.md` の「ドキュメントはコードから引き出せない情報限定」「memory・ドキュメントを引用する前に grep verify」の実行版。drift しているドキュメントは無いより悪い（嘘の能動的拡散）ので機械的に検出する。

**前提**: コード = 真実、ドキュメント = 派生。食い違いはドキュメントを直す（コードを直すことは原則ない）。

## 使い方

リポジトリルートで以下を実行:

```bash
./.claude/skills/docs-audit/scripts/audit_all.sh
```

4 つの Step が順次実行される（個別に走らせたければ `scripts/<step>.sh` を直接呼ぶ）:

| Step | スクリプト | 何を見るか |
|---|---|---|
| 1 | `extract_identifiers.sh` | ドキュメント内の識別子がコードベースに実在するか |
| 2 | `check_deleted.sh` | `rejected.md` の削除済み機能が他ファイルに残っていないか |
| 3 | `check_counts.sh` | 「N テーブル」「N タブ」等の数値主張が実装の宣言数と一致するか |
| 4 | `verify_memory.sh` | プロジェクト memory に登場する識別子が現コードに残っているか |

`references/skip-identifiers.txt` に Swift 標準型・一般語の除外リストがある。Step 1 の誤検出が多ければここに追加する。

## 結果のまとめ方

スクリプトの生出力を読み、**重大度別**にユーザーへ報告する。各項目に必ず `ファイルパス:行番号` を添える。

```markdown
## 重大度別サマリ

### 🔴 High（嘘の記述・能動的誤情報）
- `docs/foo.md:LL`: X と書いているが実コードは逆。修正必須

### 🟡 Medium（古い・実状とズレ）
- `CLAUDE.md:LL`: N タブと書いているが実装は M タブ

### 🟢 Low（軽微・残骸）
- `keynaco/Debug/Bar.swift:LL`: 削除済み機能のキー名が残存（無害だが原則違反）
```

修正可能なものは具体的な書き換え案を提示する。重大度の目安:
- **High**: ドキュメントが「コードと逆の主張」をしている（読んだ人を能動的に誤誘導する）
- **Medium**: 古い数値・名前変更後の旧名・存在しないクラス名（事実誤認だが方向は合っている）
- **Low**: デバッグスナップショットのキー名・コメント文字列など本番無害な残骸

## やってはいけないこと

- **コードを書き換えてドキュメントに合わせる**: 原則として禁止。コード = 真実、ドキュメント = 派生。例外は「ドキュメントが正しく、コードがバグっている」と判明したときのみで、その判定にはテスト失敗・コミットメッセージ・`rejected.md` エントリのいずれかの証拠を要する
- **`rejected.md` の機能名を削除する**: 記録目的なので削除済み機能名が登場するのは正しい。Step 2 のスクリプトも `rejected.md` 自身は除外している
- **整合させるために docs/ にエントリを書き足す**: 「N テーブル」を 4 から 5 に更新するなら良いが、新しい behavior spec を `docs/` に追記するのは `retrospectives.md` の原則違反。該当変数/関数の `///` ドキュメントコメントに書く

## スクリプトの限界と人手判断が要る箇所

- **Step 1**: バッククォート囲み識別子しか見ない。地の文の言及（`foo関数` のように埋め込まれた識別子）は拾えない
- **Step 2**: `rejected.md` の見出しから「削除」「廃止」「不採用」を含むセクションのみ対象。Markdown 構造に依存
- **Step 3**: 数値主張は「N + 半角スペース + 単語」のパターンのみ検出（「5つ」のような表記は拾えない）
- **Step 4**: memory ファイル内の識別子をコードベースに照合するだけ。memory の本文が古い意見である場合は人間判断が必要
- **Step 5（手動）**: CLAUDE.md / memory / SKILL.md の重複検出はスクリプト化していない。同じ情報を 2 箇所に書いていないか目視確認する

## 不変条件

- スクリプトは **read-only**。発見した drift を修正する場合は、必ずユーザーに修正計画を提示してから着手する
- 「すべて整合している」と報告する前に、少なくとも Step 1〜3 を実行している
- スクリプトを増やしたくなったら `scripts/` に追加し、`audit_all.sh` から呼ぶ。SKILL.md の表も更新する
