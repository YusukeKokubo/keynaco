# N-gram / 変換履歴の LLM クレンジング

## 背景

IME を使い続けると `history` / `bigram` / `trigram` / `skip_bigram` に誤変換・誤操作由来のノイズが蓄積する。
既存の `performGCIfNeeded()` は「古い低頻度エントリ」を時間経過で除去するが、「確定したが意図しなかった変換」は count が増えてむしろ上位に居座る。
LLM を使ってこのノイズを検出・除去する。

---

## 提案 1：LLM によるバッチ評価 → 自動削除

### 概要

`DatabaseManager` から全エントリ（または最近の N 件）を取得し、`FoundationModels` に「読み→変換の自然さ」を評価させる。
`delete` 判定のエントリを自動的に DB から削除する。

### 評価軸

| テーブル | LLM に渡すコンテキスト | 判定基準 |
|---------|----------------------|---------|
| `history` | `input`（読み）→ `output`（変換） | 日本語として自然な読み→漢字変換か |
| `bigram` | `prev` → `output` | 文章中で自然につながる2語か |
| `trigram` | `prev2` → `prev1` → `output` | 3語の連鎖として自然か |
| `skip_bigram` | `prev` → `output`（間に他語あり）| 文章内で共起しうる2語か |

### バッチ設計

1. `fetchAll*` で全エントリ取得（上限 1000 件）
2. エントリを 50 件ずつ JSON 配列にまとめてプロンプトに渡す
3. LLM のレスポンスは `[{"id": 0, "verdict": "keep" | "suspect" | "delete"}, ...]` のJSON
4. `delete` を即時削除、`suspect` は提案 2 のレビューキューに積む

### プロンプト案

```
以下は日本語IMEの変換履歴エントリです。各エントリについて、日本語として自然な変換かどうかを判定してください。
- keep: 自然な変換
- suspect: やや不自然（ユーザー確認が必要）
- delete: 明らかに誤変換・ノイズ（例: 読みと変換の意味的関連が皆無）

エントリ:
[{"id":0,"input":"とう","output":"東"},{"id":1,"input":"ks","output":"草"},...] 

JSON配列で verdict のみ返してください。
```

### 新規コンポーネント: `LLMCleanser`

```swift
// Core/Sources/Core/LLMCleanser.swift
public actor LLMCleanser {
    public enum Verdict: String, Codable { case keep, suspect, delete }
    public struct EvaluatedEntry {
        public let table: String
        public let key: [String: String]  // primary key columns
        public let verdict: Verdict
    }
    public func evaluate(db: DatabaseManager) async -> [EvaluatedEntry]
    public func applyAutoDelete(db: DatabaseManager, entries: [EvaluatedEntry])
}
```

### トリガー

- `SettingsWindowController` の「クレンジング」ボタン押下時に手動実行
- オプション: アプリ起動後 24 時間以上経過していれば自動実行（`UserDefaults` でタイムスタンプ管理）

## 提案 2：LLM が列挙した怪しいエントリをユーザーがレビュー

### 概要

提案 1 の `suspect` / `delete` 判定エントリを設定画面に一覧表示し、ユーザーが確認してから削除する。
誤削除リスクをゼロにできるため、`delete` 自動削除に抵抗があるユーザーへのフォールバックにもなる。

### UI: `CleanserViewController`（設定画面の新タブ）

```
[ クレンジング ]
  ─────────────────────────────────────────
  LLM が怪しいと判定したエントリ（12 件）
  ─────────────────────────────────────────
  [✓] history   "ks" → "草"         [削除]
  [✓] bigram    "草" → "wwww"       [削除]
  [ ] history   "きかい" → "機械"    [削除]
  ...
  ─────────────────────────────────────────
  [選択削除]  [すべて削除]  [再スキャン]
```

- チェックボックスで個別選択→まとめて削除
- 各行に理由（LLM の verdict と短いコメント）を表示
- 「再スキャン」で LLM 評価を再実行

### 設定画面への統合

既存の `NSTabViewController` に `CleanserViewController` を追加（「クレンジング」タブ）。

---

## 実装フロー（段階的）

```
Phase 1  LLMCleanser の評価ロジック実装 + テスト
         └─ FoundationModels 利用不可時は UI を無効化
Phase 2  CleanserViewController UI 実装（設定タブ追加）
Phase 3  自動実行オプション（起動時バックグラウンドスキャン）
```

---

## 制約・注意点

- `FoundationModels` は macOS 26 + Apple Intelligence 必須。利用不可時は機能を非表示にする（`LLMMisconversionChecker` と同じパターン）
- `bigram` の `is_preset = 1` 行はクレンジング対象外（プリセット行を誤削除しない）
- LLM へ送るデータはローカル処理のみ（オンデバイス）。個人的な変換履歴がクラウドに送信されない点を設定画面に明記する
- バッチ評価中はプログレスインジケータを表示し、キャンセル可能にする
