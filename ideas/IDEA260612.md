# ホットパス計測結果と改善案（2026-06-12）

## 計測概要

- Debug ビルド、PID 26385
- ツール: `xctrace` Time Profiler（45s録画）+ `heap` スナップショット
- 負荷: ソケット経由で「kanzi + Space + Enter」を 200 ループ（2.7–3.2 req/s）
- ホットパス: `InputHandler.handle()` → `buildCandidateList(.whileTyping)` → `collectCandidateSources` → `requestCandidates`

## 計測結果

### CPU 時間の内訳（Main Thread: 30.72s）

| 関数 | 時間 | 割合 |
|---|---|---|
| `Kana2Kanji.kana2lattice`（AzooKey） | 19.98s | 65% |
| `SetAlgebra.init(arr...)` ← kana2lattice 内部 | ≈12s | 40% |
| `DatabaseManager.fetchHistoryScoredMerged` | ほぼ 0 | 無視できる |
| `DatabaseManager.fetchUserDictCombined` | ほぼ 0 | 無視できる |
| `InputHandler.assembleCandidateList` | 微小 | 無視できる |

Worker Thread（0x3fff6d）でも `Kana2Kanji.updateNe...` が 32.19s / 72%。AzooKey が Main + Worker 合わせて CPU の大半を占有。

### ヒープ（200 ループ前後）

- ロード前: 128,634 nodes → ロード後: 138,351 nodes（+7.5%）
- keynaco 固有オブジェクト（DicdataElement / LatticeNode / RegisteredNode）は**増加ゼロ**
- 増分の大半は SQLite 内部バッファ等の小オブジェクト（32–64 バイト帯）

### 前回コミット（perf: reduce per-keystroke allocations）の効果

効いている。per-keystroke の Swift オブジェクトはループしても積み上がらない。ただし支配的なコストは AzooKey 内部にあるため、体感速度への直接的な寄与は限定的。

## 結論

> **ボトルネックは AzooKey（`requestCandidates` / `kana2lattice`）。DB は問題ない。**

AzooKey 内部の `SetAlgebra.init(arr...)` ― Array から Set を毎回構築する操作 ― が全体の約 40% を占める。これは AzooKey の内部実装なので keynaco 側から直接は変えられない。

## 改善案

### A. `.whileTyping` のデバウンス（効果: 大）

キーを打つたびに `requestCandidates` を呼ぶのをやめ、入力が止まってから 50–100ms 後に一度だけ呼ぶ。  
その間はひらがな候補だけ即時表示して、AzooKey 結果が返ってきたら差し替える。

- **メリット**: AzooKey の呼び出し回数を大幅削減。「かんじ」と打つ 5 キーが 1 回呼び出しになる
- **デメリット**: 候補表示に数十ms の遅延が生じる。実装がやや複雑（タイマー管理）
- **実装ポイント**: `buildCandidateListInternal` のエントリで `Task.sleep` or `DispatchWorkItem` でデバウンス。キャンセル処理が必要

### B. reading が変わっていなければ AzooKey をスキップ（効果: 中）

`collectCandidateSources` の入口で「前回呼んだ reading と今回が同じか」を比較し、同じなら AzooKey 結果をキャッシュから返す。

- **メリット**: Space 連打（候補送り）や同一 reading での再ビルドで AzooKey を省略できる
- **デメリット**: `.explicit` トリガー（Space 押下）では既にキャッシュが効いているケースが多い。`.whileTyping` では reading が毎回変わるので恩恵は薄い
- **実装ポイント**: `InputHandler` に `lastAzooKeyReading: String?` と `lastAzooKeyResult` を持たせる

### C. 現状維持

AzooKey の速度は外部要因であり、改善できる上限がある。デバウンスの UX コストを払いたくなければ許容する選択肢。体感で「遅い」と感じなければ優先度低。
