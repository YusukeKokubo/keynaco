# 打鍵中 prefix focus のモーラ閾値・見直し案（2026-06-14）

打鍵中（`.whileTyping`）に前方一致の履歴・ユーザー辞書を初期フォーカスするかどうかを、品詞別モーラ閾値で制御している。現状は名詞・固有名詞 2 / 動詞 3 / 形容詞 3 / 未分類（`unknown`）5、助詞・助動詞は対象外、読み完全一致は閾値なしで最優先。この配分の妥当性を検討したメモ。

形容詞は当初 `unknown` と同じ 5 だったが、語幹の予測力に合わせて 3 へ分離済み（c99c2e5）。以下の評価・代替案はこの分離後を前提に書き直してある。

## 現行案（2 / 3 / 3 / 5）の評価：条件付き賛成

「曖昧さ・リスクが高いカテゴリほど確証（モーラ数）を多く要求する」という原則は正しく効いている。形容詞を unknown から切り出して動詞と同じ 3 にしたことで、当初引っかかっていた「性質が真逆のものを同じ閾値にしている」問題は解消した。日本語のイ形容詞は閉じた小さいクラスで語幹が語をほぼ一意に決める（「おもしろ」→「面白い」はほとんど散らばらない）ため、動詞と同程度の確証で出してよい。

残る本丸は `だけんす`(4) + 履歴「打鍵数削減」のケース。確定直後で `pos`/`lcid` 未設定だと履歴が `unknown`=5 に落ち、ユーザーが自分で確定したばかりの語が次に負ける。履歴はユーザーが明示的に承認した最強のシグナルなのに、品詞が付くまで冷遇される。非同期分類（`schedulePOSClassification`）で後から直るとはいえ、初回体験が悪い。

ここから言えるのは、前方一致でも「履歴由来」か「辞書由来」かで扱いを分けるべきということ。今は読み完全一致だけ閾値なしで、前方一致は出自を問わず品詞閾値。前方一致でも履歴由来はユーザー承認済みなので、辞書由来より緩めて筋が通る。

## 代替案

### 案A：形容詞を切り出して 3（実装済み・c99c2e5）

名詞2・動詞3・形容詞3・unknown5。形容詞を語幹の予測力に合わせて動詞と揃えた。ふつうの文章をよく書く人に効く（形容詞の出番が多く効きを体感しやすい）。残るリスクは「うれし」「かなし」など 3 モーラ形容詞語幹が活用形の途中で意図せずフォーカスを取ること。「うれし」→「嬉しい」を出した瞬間に「嬉しかった」と打ちたかったというズレが起きうる。ただし前方一致サジェストは確定を強制しないのでコストは小さく、実機で「うるさい」と感じないか経過観察する。

### 案B：履歴由来の前方一致を上限 3 にクランプ（次に推す）

辞書由来は現状どおり 2/3/3/5、ただし履歴由来の前方一致だけ上限 3 をかぶせる（`min(品詞閾値, 3)`）。`unknown`=5 でも履歴なら 3 で拾え、`だけんす`(4) は余裕でフォーカスする。「自分が一度確定した語は積極的に出す、辞書の海からの推測は慎重に」という履歴重視の差別化軸とまっすぐ合う。固有名詞・専門用語をくり返し打つ keynaco の想定ユーザーに向く。リスクは、誤って一度確定してしまった語が早めに復活しやすくなること。ただし Shift+Delete で消せるので回収可能。実装も履歴行に上限クランプを一個足すだけで、カテゴリ別閾値表を触らずに済むのが良い。

### 案C：unknown を捨てて「履歴なら名詞扱い、辞書なら最保守」

`unknown` という箱をやめ、未分類は出自で振り分ける。履歴由来の未分類は名詞=2（履歴に載る未知語は固有名詞・専門用語が大半という経験則）、辞書由来の未分類だけ 5。案B より踏み込んだ版で初回履歴がほぼ即フォーカスする。新語・固有名詞をどんどん登録する上級ユーザー向け。リスクは案B より高く、ユーザー辞書に変なエントリがあると 2 モーラで暴発する。案B のクランプ方式のほうがリスク/効果のバランスが良い。

## 各論

- **品詞の切り方**：形容詞を unknown から分けて 3 にしたのは済み。固有名詞を名詞と同じ 2 にするのは賛成（むしろ固有名詞こそ補完価値が高い）。ただし 2 モーラ固有名詞プレフィックスは曖昧さも最大級（「とう」で東京/東芝/…）なので 2 より下げるのは勧めない。
- **助詞・助動詞の例外**：設けないほうがよい。「という」「について」は熟語的だが、まさに打鍵中に頻出する語で、ここでフォーカスを奪うのがリズム破壊の典型。除外ルールの単純さを保つ価値のほうが大きい。読み完全一致で履歴に載れば別経路で拾える。
- **完全一致だけ閾値なし**：現状維持に賛成。その読みで前に確定した実績がある＝最強のシグナル。動詞だからと 3 モーラ要求するのは差別化軸に逆行する。完全一致に閾値を足すのは反対。
- **unknown=5**：辞書由来には 5 で安全寄り、これは正しい。危険なのは履歴由来も巻き込んでいること。名詞っぽさを読みの形だけで当てるのは精度が出にくいので、品詞推定ではなく出自で振り分ける案B/C のほうが堅実。

## 先例・理論

モーラを単位に選んでいるのは筋が良い。Mozc / Google 日本語入力や ATOK の予測変換は文字数や学習モデルベースで、明示的な品詞×モーラ閾値というルールは表に出さない（裏のスコアに溶けている）。文字数ではなくモーラを使うのは、日本語の音韻的コミットメントの単位に合っている（拗音を mora_count で 1 と数える今の実装含めて理にかなう）。

HCI 的には「誤サジェストのコスト > 欠落サジェストのコスト」という非対称性が効く。外せば無視して打ち続けるだけ（低コスト）、出しゃばって誤フォーカスすると注意資源を奪う（高コスト）。この非対称が「打鍵中は保守的に」という哲学を裏付ける。悩むなら高い側に倒すのが安全。

## 優先して試す A/B

形容詞 3（案A）は実装済み。実機で次を経過観察する。

- `おもしろ`(4) で辞書「面白い」がフォーカスしてうるさく感じないか。
- `うれし`(3) が活用途中で邪魔しないか。

次に案B（履歴由来の前方一致を上限 3 クランプ）を試す。

- `だけんす`(4) + 履歴「打鍵数削減」→ クランプ前は unknown=5 で負ける／クランプ後は 3 で勝つ。狙いどおりに直るか。
- `たべ`(2) + 履歴「食べる」→ 動詞は履歴でも min(3,3)=3 で 2<3 なのでフォーカスしないまま。リズム入力が守られるか確認。
- `おもしろ`(4) + 履歴「面白い」→ 形容詞 3 で履歴・辞書とも既にフォーカスするので、案B の影響は unknown 行に限られる。

案A は形容詞、案B は履歴由来全般と直交するので、案A の経過観察と並行して案B で初回履歴の体験を直す順がよい。
