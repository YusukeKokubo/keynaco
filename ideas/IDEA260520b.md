# N-gram 学習時に複合語を分割記録する

## 背景

`recordBigram(prev:input:output:)` は確定単位を 1 トークンとして記録するため、ユーザーが AzooKey 候補から「予定です」のような**複数文節を含む表層**を一括確定するとそれが 1 bi-gram になる。一度学習すると prev → "予定です" として何度も Successor で提示され、「名詞＋述語」型の長いサジェストが量産される。

[IDEA260520.md](IDEA260520.md) は**表示時に prefix 分割**することで救済する案だが、こちらは**学習時に分割記録**して根本から問題を断つ案。

## 提案

`confirmSuccessor` / `pushCommitted` / 通常の確定経路で N-gram を記録するとき、確定文字列を azooKey の `segmentize` にかけて文節分割し、**文節単位の bi-gram / tri-gram として記録**する。

```
ユーザー確定: "予定です"
  ↓ segmentize
[予定 / です]
  ↓ 分割記録
recordBigram(prev: <previous>, output: "予定")
recordBigram(prev: "予定", output: "です")
```

## 設計の方向性

1. **対象経路**: `confirmSuccessor` / `InputHandler+NormalInput.swift` の確定経路 / セグメント確定の `pushCommitted` 呼び出し
2. **分解条件**: 確定文字列が 2 文節以上のときのみ分割。1 文節（"予定" 等）はそのまま単一トークンとして記録（既存挙動）
3. **`committedHistory` の扱い**: ここが要設計。
   - 案 A: 分割して複数 push する（後続の prev 連鎖がより細かくなる）
   - 案 B: `committedHistory` には元の表層を 1 トークンとして push し、DB 記録のみ分割する
   - **案 A 推奨**: Successor の連鎖表示・skip-bigram 計算が細粒度で効く
4. **読み情報**: `recordPrefixes(reading:output:)` は文節ごとの読みが必要。AzooKey の変換結果から `Segment` 構造を再構築できる経路（既存のセグメントモード実装と同じ）を流用
5. **過去に学習済みの複合 bi-gram の扱い**: 既存 DB 行は触らない（破壊的マイグレーションは避ける）。新規確定から細粒度学習に切り替えれば、time-decay で徐々に複合行のスコアが下がる

## 影響範囲

- `Core/Sources/Core/InputHandler+SuccessorMode.swift` の `confirmSuccessor`
- `Core/Sources/Core/InputHandler.swift` / `+NormalInput.swift` の確定パス全般
- `Core/Sources/Core/InputHandler+SegmentMode.swift` のセグメント確定
- `DatabaseManager` 自体は変更不要（既存の record API をループで呼ぶだけ）

## 懸念点

- **読み復元の難しさ**: 表層 → 文節分割後の各文節の読みを正確に復元する経路が必要。AzooKey の `requestCandidates` 結果からセグメントごとの読みを取れるかは要調査。失敗時は読み記録のみスキップする fallback が必要
- **`committedHistory` 細粒度化の副作用**: `sentenceTerminators` リセット・`mostRecentContentWords` の particles フィルタ・`successorLLMContext` の `suffix(3)` などが「履歴 1 要素 = 1 文節」前提でなかった場合に挙動が変わる可能性。要監査
- **セグメントモードでの確定経路**: そもそもセグメントモードでは既に文節単位で確定している（はず）ので、対象は主に「Space 1 回で AzooKey top-1 を採用するパス」と「Successor 採用パス」になる
- **学習量の増加**: 分割記録すると DB 行が増える。time-decay GC は既存通り効くが、初期成長が早くなる

## 優先度・難易度

| 項目 | 評価 |
|------|------|
| 期待効果 | 中〜高（既存の複合 bi-gram は time-decay で消えるまで時間がかかる。即効性は表示時アプローチに劣る） |
| 難易度 | 中〜高（読み復元 / `committedHistory` 細粒度化の影響範囲監査が大きい） |
| リスク | 中（既存テストや学習挙動への影響が広範） |
| 着手タイミング | IDEA260520（表示時 prefix 分割）で体感改善を確認後、根本対策として検討 |
