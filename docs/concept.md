# keynaco のコンセプト

「**何のために存在するか**」「**何で差別化するか**」を記す。新機能を検討するときの判断基準。

「どう作るか」のメタルールは [`retrospectives.md`](retrospectives.md)、捨てた機能は [`rejected.md`](rejected.md)、経過観察中の機能は [`observation.md`](observation.md)。

---

## なぜ keynaco を作るか

出発点は AzooKey のライブ変換への不満。

- ライブ変換は「打った瞬間に確定っぽい候補を表示する」方式で、視覚フィードバックは速いが、**読みを最後まで打ち切ってから候補を選ぶ運用に近くなる**
- 結果として **タイプ数が多くなり、完全一致変換が中心**になる
- 前方一致・部分一致・履歴からの予測が活きにくい

keynaco は **「打鍵を最小化するローカル完結 IME」** を目指す。ライブ変換とは別の方向で打鍵削減を取りに行く。

| IME | ローカル完結 | LLM 補強 | macOS ネイティブ |
|-----|------------|---------|----------------|
| ことえり | ○ | ✗ | ○ |
| Google 日本語入力 | △ | ✗ | ○ |
| ATOK | △ | △ | ○ |
| mozc | ○ | ✗ | △ |
| azooKey-on-macOS | ○ | ○ | ○ |
| **keynaco** | ○ | ○ | ○ |

技術スタックは azooKey-on-macOS と近い（AzooKey + Zenzai）。**差別化はエンジン部分ではなく、入力体験の設計思想で取る**。

### エンジン追従は思想ではなく義務

同じエンジン（AzooKey + Zenzai）に乗る以上、**変換品質では並ぶのが上限**で、エンジンの改善は本家 azooKey に先に入る。keynaco は構造的に**エンジンの追従者**。ここで重要な区別:

- **機能の取捨**（ライブ変換を持たない・Tuner を使わない・LLM を盲信しない）は**意図的な設計判断**であり、強み。
- **エンジンのバージョン遅れ**（例: AzooKey 0.11.2 のため zenz-v3.2 の右文脈 `` を使えない）は**設計判断ではなく純粋な弱み**。追従しない理由がないものは追従する——遅れても得るものがゼロだから。

→ AzooKey / Zenzai の更新（モデル版・API・新機能）は「思想に合うか」を問う前に、**まず追従する前提で評価する**。差別化は体験の層でやり、エンジンの層では後れを取らないのが原則。新機能検討で「これは体験の差別化か、それともエンジン追従か」を切り分けること（追従なら速やかに、差別化なら指針 1-5 で判断）。

## 設計の指針

### 1. 機能語と内容語でサジェスト価値が違う

- **機能語**（助詞・助動詞・接続詞）はリズムでタイプするのでサジェストはストレス源
- **内容語**（名詞・固有名詞）はサジェストが助かる
- → 一律にサジェストする現状の IME とは違い、語種で挙動を切り替える

### 2. ローカル完結を犠牲にしない

- 入力データはユーザーが打つすべての文字が通る場所。**端末から出さない**
- LLM 補強もローカル推論（Zenzai = llama.cpp）。クラウド変換に逃げない
- 「ユーザー数 → データ収集 → 精度向上」というループには乗らない設計

### 3. 履歴は使うほど自分仕様になる

- 時間減衰スコア付きの履歴で、使うほど自分の語彙に最適化される
- 学習データはローカルの SQLite に閉じる
- マシン間で共有したい場合は NAS 同期（自分でコントロールする経路）

### 4. macOS ネイティブに振り切る

- クロスプラットフォーム互換性は捨てる
- InputMethodKit + Swift 6 + macOS 26 を前提に最適化
- IMK の不安定な部分（候補ウィンドウ等）は自作で置き換える

### 5. LLM を盲信しない

- 効果が測れなかった LLM 機能は容赦なく削る（LLMPOSClassifier・LLMSegmentConverter・Zenzai の `topic`/`style`/`preference` UI など）
- 削除判断は [`rejected.md`](rejected.md) に記録、経過観察中は [`observation.md`](observation.md) で追跡

## このコンセプトに合致しない機能の例

- 入力データをサーバーに送る予測（指針 2 違反）
- 助詞入力中にも候補ウィンドウを大きく出す UI（指針 1 違反）
- 「とりあえず LLM を使う」機能（指針 5 違反）
- Windows / Linux への移植（指針 4 違反）

新機能を検討するときは「上記指針のどれを強化するか」「どれにも該当しないなら本当に必要か」を確認する。
