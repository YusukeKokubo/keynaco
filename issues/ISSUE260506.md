# ISSUE260506: Space なし Enter 確定で複合仮名がカタカナ混じりになる

## 症状

`kyo` と入力して **Space を押さずに Enter** で確定すると、`きょ` ではなく `きョ`（ひらがな き + カタカナ ョ）が挿入される。

同様に影響する入力: `nyo`, `hyo`, `myo`, `ryo`, `byo`, `pyo` など小文字ょを含む複合仮名全般。

## 再現手順

```
1. keynaco (Debug) でソケットサーバーを起動
2. k → y → o と入力
3. Space を押さずに Enter
4. 挿入テキストが "きョ" になる（期待: "きょ"）
```

## 原因

### 1. AzooKey が "きョ" を候補として返す

`buildCandidateList(autoShow: true)` で `requestCandidates(hiragana: "きょ", richCandidates: false)` を呼ぶと、AzooKey が以下を返す:

```
["きょ", "キョ", "きョ", "居", "挙", ...]
         ^固定   ^固定   ^AzooKey最初
```

`candidates[2] = "きョ"` はひらがな き (U+304D) + カタカナ ョ (U+30E7) の混合文字。
AzooKey 上流の問題と見られる。

### 2. `initialRow = fixedCount = 2` で AzooKey 最初の候補が自動選択される

`assembleCandidateList` の以下のロジックにより、初期選択行が固定候補（ひらがな/カタカナ）の直後になる:

```swift
let preferHiragana = !hiraganaInHistory && Self.isHiraganaPreferred(h)
let initialRow = (candidates.count > fixedCount && !preferHiragana) ? fixedCount : 0
```

`isHiraganaPreferred("きょ")` は `false`（助動詞・接続詞等のパターンに非該当）なので `initialRow = 2`。

### 3. Enter が auto-show 済み候補ウィンドウの選択行を確定する

候補ウィンドウが auto-show で表示された状態で Enter → `handleCandidateVisible` → `doConfirmSelection` が `selectedText = candidates[2] = "きョ"` を確定する。

## 発見経緯

PLAN260506c リファクタリング後の IME サンドボックス確認中に検出。  
`git show HEAD~1` でリファクタリング前のコードも同一ロジックを持つことを確認済み。**リファクタリング由来ではなく既存バグ。**

## 修正案

### 案A: AzooKey 候補から混合文字（ひらがな＋カタカナ混在）を除外

`collectCandidateSources` または `assembleCandidateList` で、ひらがなとカタカナが混在する候補をフィルタする:

```swift
// 全ひらがな または 全カタカナ（+漢字等）でない候補を除外
let isScriptMixed = { (s: String) -> Bool in
    let hasHiragana = s.unicodeScalars.contains { $0.value >= 0x3041 && $0.value <= 0x3096 }
    let hasKatakana = s.unicodeScalars.contains { $0.value >= 0x30A1 && $0.value <= 0x30F6 }
    return hasHiragana && hasKatakana
}
azooKeyCandidates = azooKeyCandidates.filter { !isScriptMixed($0) }
```

### 案B: `isHiraganaPreferred` の対象を拡張し短い読みでひらがな優先

2〜3文字の純ひらがな入力では `preferHiragana = true` にして `initialRow = 0`（ひらがな固定行）を指すようにする。  
ただし「きょう」「しょくじ」等の長い読みは変換結果を優先したいため閾値設定が難しい。

### 推奨

**案A** を優先。AzooKey が返す混合文字はどのシナリオでも有用でないため除外コストが低い。
