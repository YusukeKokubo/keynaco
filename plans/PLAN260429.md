## ④ コード調査（最優先）

### 問題

`→` キーを候補選択中に押したときの挙動が、ドキュメントの意図とコードで食い違っている。

**ドキュメント（states.md 状態遷移図・scenarios.md S-02）の記述:**
```
候補選択中 --> 組成中 : →（ひらがな組成に戻す）
→ キーは applyMarkedText + .dismiss でひらがな組成に戻す。
insertText を使うと Electron 系アプリに半角スペースが挿入されるため使わない。
```

**現在のコード（`InputHandler+Candidates.swift` `handleCandidateVisible`）:**
```swift
case KeyCode.rightArrow:
    commitComposition(client: client)   // insertText を呼ぶ
    return (true, suggestSuccessors())
```

`commitComposition(client:)` はデフォルト引数 `candidate: .hidden` で呼ばれるため、選択候補を無視して組成テキスト（ひらがな）を `insertText` で確定し、待機状態へ遷移する。

### 2つの解釈

**A. ドキュメントが正しい（コードが regression）**
- `applyMarkedText + .dismiss` に戻し、候補を閉じてひらがな組成に戻る（Electron 安全）
- 状態遷移: 候補選択中 → 組成中

**B. 現コードが正しい（ドキュメントが古い）**
- `→` は「選択せずに組成テキストを確定」= 組成中の `→`（Enter と同じ）と一貫
- 状態遷移: 候補選択中 → 待機（または Successor モード）
- Electron 問題が実際に発生するか検証が必要

### 調査アクション
1. Electron 系アプリ（例: Slack, VS Code）で候補選択中に `→` を押して半角スペースが挿入されないか確認
2. 結果に応じて A / B どちらかに統一し、コードまたはドキュメントを修正

## ①③ glossary.md 修正内容

### ① `historyEnd`

```diff
- ### historyEnd
- 履歴セクションの末尾インデックス。これより前が「履歴候補」、以降が「辞書候補」。
+ ### historyEnd
+ 候補リスト内の「固定候補 + 予測候補 + 履歴候補」セクションの末尾インデックス。
+ `historyEnd = fixedCount + predictCount + historyCount`。
+ これ未満の候補は Shift+Delete で削除可能。これ以降は AzooKey 専用候補（削除不可）。
```

### ② `autoShow`

```diff
- ### autoShow
- 文字入力中に候補ウィンドウを自動表示するかどうか。履歴・辞書・bi-gram がすべて 0 件なら表示しない。
+ ### autoShow
+ 文字入力中に候補ウィンドウを自動表示するかどうか。履歴・辞書・予測候補（tri-gram + bi-gram）がすべて 0 件なら表示しない。
```

### ③ `fixedCount`

```diff
- ### fixedCount
- 候補リスト先頭の固定枠数（ひらがな・カタカナ）。スクロールアウトしない。
+ ### fixedCount
+ 候補リスト index 0 から始まる固定枠数（ひらがな・カタカナ）。
+ 初期選択行は `fixedCount` から始まるため、↑ キーで遡らないと見えない。
```


### ④-B（コードが正しい場合）ドキュメントを修正

**状態遷移図:**
```diff
- 候補選択中 --> 組成中 : →（ひらがな組成に戻す）
+ 候補選択中 --> 待機 : →（組成テキストを確定）
```

**状態テーブル（候補選択中）:**
```diff
- | Enter / → | 選択候補を確定 → 待機（→ はひらがな組成に戻してから Enter 相当） |
+ | Enter | 選択候補を確定 → 待機 |
+ | → | 組成テキストを確定 → 待機（選択候補は無視） |
```

### ⑤ Successor モードトリガー

```diff
- 待機 --> Successorモード : 確定直後に bi-gram 候補 or 格助詞 fallback が存在
+ 待機 --> Successorモード : 確定直後に tri-gram / bi-gram 候補 or 格助詞 fallback が存在
```

補足テキストも同様:
```diff
- 候補取得の優先順位: ... なければ lastCommittedOutput だけで bigram をフォールバック
+ 候補取得の優先順位: prev2Output × lastCommittedOutput で trigram を優先し、
+   なければ lastCommittedOutput だけで bigram をフォールバック
```
