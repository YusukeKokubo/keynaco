# content_bigram 移行計画

## 目的

`noun_bigram` を `content_bigram` に拡張し、名詞・固有名詞に加えて動詞も prev に含めることで、バイグラム予測の対象と蓄積効率を改善する。

## 設計方針

- **記録対象 POS**: `noun | proper_noun | verb`（形容詞・助詞・その他は除外）
- **`prev` に入れる値**: 動詞は LLM 分類応答から取得した基本形（lemma）に正規化、名詞・固有名詞は表記そのまま
  - `NLTagger(.lemma)` は日本語活用形に対して lemma を返さないためフォールバックのみに使用
  - LLM が lemma を返せない場合（confidence 低・other 等）は表記そのままで記録（surface 蓄積にフォールバック）
- **DB テーブル名**: `noun_bigram` → `content_bigram`（カラム構成は変更なし）
- **fetch フィルタ**: `count >= 2`
- **既存データ**: 個人アプリのためゼロベースでリセット（マイグレーション不要）

## 実装ステップ

### Step 1: DB 変更

- `DatabaseManager.swift`: `noun_bigram` テーブル定義を `content_bigram` に変更
- `DatabaseManager+Ngram.swift`: 全メソッドのテーブル参照を `content_bigram` に変更
  - `recordNounBigram` → `recordContentBigram`
  - `fetchNounBigram` → `fetchContentBigram`（`WHERE count >= 2` を追加）
  - `fetchNounBigramTop` → `fetchContentBigramTop`
  - `fetchAllNounBigram` → `fetchAllContentBigram`
  - `deleteNounBigramEntry` → `deleteContentBigramEntry`
- `DatabaseManager.swift:cleanupLegacyTables()`: `noun_bigram` を廃止テーブルリストに追加

### Step 2: POSCommitSequencer 変更

- `NounState` → `ContentWordState` にリネーム
- `applySideEffects` の記録条件を拡張:
  ```swift
  // before
  guard classification.pos == "noun" || classification.pos.hasPrefix("proper_noun") else { return }
  // after
  let isContentWord = classification.pos == "noun"
      || classification.pos.hasPrefix("proper_noun")
      || classification.pos == "verb"
  guard isContentWord else { return }
  ```
- 動詞のとき `prev` に LLM から得た基本形を入れる（`Classification` に `lemma: String?` を追加して引き回す）

### Step 3: LLMPOSClassifier のレスポンス拡張

**プロンプト変更**: 動詞の場合は `tag:confidence:lemma` 形式で基本形も返させる。

```
# Response format
- Default: "tag:confidence"  (e.g. noun:high)
- Verb only: "verb:confidence:lemma"  (e.g. verb:high:行く)

# Examples
行った → verb:high:行く
設定した → verb:high:設定する
確認して → verb:high:確認する
書きます → verb:high:書く
欲しい → adjective:high
が → particle:high
```

**`Classification` に `lemma` を追加**:

```swift
public struct Classification: Sendable, Equatable {
    public let pos: String
    public let posTag: String
    public let posRetry: Bool
    public let lemma: String?  // 動詞のみ。LLM が返せない場合は nil
}
```

**`normalizeTag` / `categoryFromTag` の拡張**: `verb:high:行く` の第3フィールドを `lemma` として抽出。

**`NLTagger` はフォールバック**: LLM が lemma を返せない場合（nil）に限り `NLTagger(.lemma)` を試み、それでも取れなければ表記そのまま。

### Step 4: InputHandler 変更

- `lastConfirmedNounOutput` → `lastConfirmedContentWordOutput` にリネーム
- `InputHandler.swift` のコメント更新

### Step 5: 呼び出し側の更新

- `InputHandler+Candidates.swift`: `fetchNounBigram` → `fetchContentBigram`
- `InputHandler+SuccessorMode.swift`: 同上

### Step 6: テスト更新

- `NounBigramTests.swift` → `ContentBigramTests.swift` にリネーム・内容更新
- `POSCommitSequencerTests.swift`: `NounState` → `ContentWordState`、動詞テストケース追加
- `InputHandlerCandidatesTests.swift`: `seedNounBigramPrediction` → `seedContentBigramPrediction`、動詞 prev のテスト追加
- `InputHandlerSuccessorTests.swift`: 同様に更新

### Step 7: ドメインドキュメント更新

- `docs/domain/architecture.md`: noun_bigram → content_bigram、動詞 prev の設計を反映
