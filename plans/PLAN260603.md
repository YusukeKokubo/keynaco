# PLAN260603: 文節分割を AzooKey Desktop（`.selecting`）に寄せる

## 目的

Space 後の文節選択モードで、AzooKey と同様に **左端文節の長さをエンジン候補の `composingCount` で決め**、フラットな候補リストから表層を選び、Enter で部分確定 → 残りで再変換する。

見た目だけ合わせるのではなく、**境界の正本**を Desktop と同型にし、keynaco 独自の読みルール（suffix 剥がし・`segmentize` 依存）による誤分割をなくす。

## 背景（きっかけ）

- `あなたは` + Space で AzooKey は **「あなた」|「は」**、keynaco は全文「貴方は」寄りだった。
- Desktop `SegmentsManager` 参考に firstClause マージ・部分確定の骨格は `0aa289b` で導入済み。
- suffix / segmentize フォールバックで見た目は寄せられていたが **`こんにちは` で破綻**（`こんにち|は` + 「今一」系）。

## わかったこと（結論）

### 1. AzooKey Desktop の正本

| 項目 | 内容 |
|------|------|
| 状態 | `.selecting`（Space 後） |
| 候補列 | `firstClauseResults` + `mainResults` マージ。**firstClause が全文のみのときは `main` から部分候補を採用** |
| Space 時の入力 | `insertCompositionSeparator` → `update(requestRichCandidates: true)` |
| Options | 予測 `.disabled`、Zenzai rich（本番 Desktop 相当） |
| 境界 | 選択候補の **`composingCount`**（keynaco: `inputLength`） |
| 境界に使わないもの | suffix ルール、`segmentize` while、読み末尾の手抜き |

参照: `SegmentsManager.swift`（`rawCandidatesList`, `updateRawCandidate`, `getCurrentMarkedText(.selecting)`）

### 2. keynaco 現状（Phase 3 後）

| 層 | 実装 | Desktop との差 |
|----|------|----------------|
| 骨格 | `InputHandler+SegmentMode` + `SegmentState` + `AzooKeyCandidateMerge` | 概ね準拠 ✅ |
| 境界決定 | `preferredMorphologicalSplitIndex`（です/は）+ 読み一致部分候補 + 従来の最長部分フォールバック | suffix / segmentize **不使用** ✅ |
| 文節リクエスト | `composingTextForSegmentSelection` + `makeOptionsForSegmentSelection` + 初回 `stopComposition` | Desktop 相当 ✅ |
| 文節入り | 2 文字以下・ひらがな優先・日時/ユーザー辞書・短い非助詞残りは通常窓 | Desktop に無いガード（意図的） |
| エンジン | Core / Xcode とも **`bbef9d2`** | ✅ 同期済（2026-06-04） |
| 候補 UI | 文節中はエンジン行先頭（予測セクション省略）+ 読み/`firstClause` 順の初期行 | 概ね準拠 ✅ |
| `clauseScopedEngineRows` | `firstClause` 同長フィルタ + prefix 再変換フォールバック **仍在** | 要整理（残タスク） |
| `segmentize()` | 境界未使用。逐次確定モック等で参照 | selecting では未使用 ✅ |
