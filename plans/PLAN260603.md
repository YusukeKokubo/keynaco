# PLAN260603: 文節分割を AzooKey Desktop（`.selecting`）に寄せる

## 目的

Space 後の文節選択モードで、AzooKey と同様に **左端文節の長さをエンジン候補の `composingCount` で決め**、フラットな候補リストから表層を選び、Enter で部分確定 → 残りで再変換する。

見た目だけ合わせるのではなく、**境界の正本**を Desktop と同型にし、keynaco 独自の読みルール（suffix 剥がし・`segmentize` 依存）による誤分割をなくす。

---

## 背景（きっかけ）

- `あなたは` 入力 + Space で、AzooKey は先頭 **「あなた」**、keynaco は **「貴方は」** 全文扱いになっていた。
- 以降 Desktop の `SegmentsManager.rawCandidatesList` / `prefixCandidateCommited` を参考に firstClause マージ経路へ移行済み。
- その後も `がくせいです`・`こんにちは` 等で **AzooKey 実機との差**が残ることが判明。

---

## わかったこと（結論）

### 1. AzooKey Desktop の正本

| 項目 | 内容 |
|------|------|
| 状態 | `.selecting`（Space 後の候補選択） |
| 候補列 | `firstClauseResults` + `mainResults` マージ（全文 firstClause のみのときは `main` のみ） |
| 境界 | 選択中候補の **`composingCount`** → `ComposingText.prefixComplete` |
| marked text | 太線 = 選択表層、細線 = `prefixComplete` 後の **残り読み**（`convertTarget`） |
| 手動調整 | `editSegment(count)` で **ComposingText カーソル**移動 → `didExperienceSegmentEdition` → `main` のみ |
| 境界の正本ではないもの | 読み末尾の固定ルール表、左からの `segmentize` while ループ |

参照: `azooKey-Desktop/.../SegmentsManager.swift`（`rawCandidatesList`, `getCurrentMarkedText(.selecting)`, `prefixCandidateCommited`, `editSegment`）

### 2. keynaco 現状（2026-06-03 時点）

| 層 | 実装 | Desktop との差 |
|----|------|----------------|
| 骨格 | `InputHandler+SegmentMode` + `SegmentState` + `AzooKeyCandidateMerge` | 概ね準拠（マージ・部分確定・Shift 矢印） |

| 旧経路 | `segmentize()` while ループは残存（境界フォールバック・テスト用） | Desktop selecting では未使用 |

### 3. 実機・テストで確認した具体例

| ID | ローマ字 | 読み | AzooKey（実機・報告） | keynaco IME（ユニットテスト） | エンジン `firstClause` 部分候補 |
|----|--------|------|----------------------|------------------------------|-------------------------------|
| 1 | anataha | あなたは | あなた \| は。先頭は貴方寄りも可 | end=3、残りは、候補に貴方/あなた ✓ | **なし**（strip/segmentize で 3） |
| 2 | gakuseidesu | がくせいです | 学生 \| です ✓ | end=4、残りです、学生 top ✓ | **なし**（strip で 4） |
| 3 | watashihagakusei | わたしはがくせい | わたし \| は \| がくせい（想定） | **1文節目 私は(4)**、残りがくせい ✗ | 変な partial `私はが:5`、`segmentize=わたしは\|がくせい` |
| 4 | konnitiha | こんにちは | composing: こん/こんにち/全文。**Space 後: こ \| にちは**（はを単独にはしない） | **こんにち \| は**、先頭「今一」✗ | **なし**（strip で こんにち\|は） |
| 5 | gakusei | がくせい | 1 文節扱い | 文節モード・残りなし | なし |
| 6 | ryuugakuseidesu | りゅうがくせいです | （未記録） | 留学生 \| です ✓ | なし（strip 7） |

**要点:**

- **助詞・助動詞の suffix 剥がし**は `anataha` / `gakuseidesu` では AzooKey に**似た見た目**になるが、`こんにちは` では **明確に壊れる**（`は` を切って「今一」等）。
- AzooKey は **`こ`（1 文字）・`こん`・`こんにち` など複数長の部分候補**を候補列に出し、Space 後の初期境界も **短い `composingCount` 側**になりうる（実機: **こ + にちは**）。
- keynaco テスト環境では **`firstClauseResults` に部分候補がほぼ入らない**（`こんにちは` で `firstClausePartials=[]`）。見た目合わせは **prefix 再変換 + suffix** に依存しており、AzooKey 寄せの本命（firstClause 部分候補）が未達。

## 目標状態（AzooKey 寄せの定義）

1. **文節境界**は `firstClauseResults`（手動編集後は `mainResults`）の **先頭部分候補の `inputLength`** のみから決める（Desktop: 選択候補の `composingCount` と同等）。
2. **`trailingSegmentSuffixes` / 1 文字助詞剥がし**は文節境界に使わない（composing 用フィルタ等と役割を分離するなら別途）。
3. **`segmentize()`** は Space 文節モードの境界決定に使わない（テスト・他機能で残すなら用途を限定）。
4. **`clauseScopedEngineRows` の prefix 再変換**は、firstClause に部分候補が安定して出たら **削除または最終フォールバックのみ**。
5. **文節モードの候補リスト**はエンジン行を主とし、履歴・辞書の混載方針を Desktop に近づける（別 PO C でスコープ分割可）。
6. **初期選択**はエンジン先頭行優先（文節中はひらがな固定で先頭を上書きしない）。
