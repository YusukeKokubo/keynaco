# PLAN260429e: B-1 セグメント境界の学習

## 概要

セグメントモードで `Shift+矢印` による境界調整を行って確定したとき、
その境界パターンを DB に保存する。次回同じ読みでセグメントモードに入ったとき、
AzooKey の初期分割ではなく保存済みの境界を使って再現する。

---

## 現状の問題

`doConfirmSegments()` は `isManuallyAdjusted` セグメントに 3x の重みで `recordPrefixes` と
`recordBigram` を記録する。この結果、例えば「きょう」→「今日」の変換は履歴として高優先で出てくるが、
次回「きょうはよいてんきです」を入力して Space を押すと、AzooKey は再び誤った境界でセグメント分割する。
ユーザーは毎回同じ境界調整を繰り返す必要がある。

---

## 実装方針

### 1. `boundary_pref` テーブルを追加

```sql
CREATE TABLE IF NOT EXISTS boundary_pref (
    full_reading  TEXT NOT NULL PRIMARY KEY,
    boundaries    TEXT NOT NULL,
    used_at       INTEGER NOT NULL
);
```

- `full_reading`: セグメントを結合した完全な読み（例: `きょうはよいてんきです`）
- `boundaries`: カンマ区切りのセグメント読みリスト（例: `きょう,は,よい,てんき,です`）
- `used_at`: 最後に使用したエポック秒（GC 対象とするため）

### 2. `DatabaseManager` にメソッドを追加

```swift
func saveBoundaryPref(fullReading: String, segments: [String]) {
    let boundaries = segments.joined(separator: ",")
    let t = nowEpoch()
    execute("""
    INSERT INTO boundary_pref (full_reading, boundaries, used_at)
    VALUES (?, ?, ?)
    ON CONFLICT(full_reading) DO UPDATE SET
        boundaries = excluded.boundaries,
        used_at    = excluded.used_at;
    """) {
        self.bindText($0, 1, fullReading)
        self.bindText($0, 2, boundaries)
        sqlite3_bind_int64($0, 3, t)
    }
}

func fetchBoundaryPref(fullReading: String) -> [String]? {
    var result: String? = nil
    queryStrings("""
    SELECT boundaries FROM boundary_pref
    WHERE full_reading = ?
    """) {
        self.bindText($0, 1, fullReading)
    }.first.map { result = $0 }
    return result.map { $0.components(separatedBy: ",") }
}
```

### 3. `doConfirmSegments()` で境界を保存

`isManuallyAdjusted` なセグメントが1つ以上ある場合のみ保存する（手動調整した場合のみ）。

```swift
// doConfirmSegments() 内、既存コードの後に追記
let hasManualAdjustment = segmentState.segments.contains(where: { $0.isManuallyAdjusted })
if hasManualAdjustment {
    let segReadings = segmentState.segments.map { $0.reading }
    db.saveBoundaryPref(fullReading: fullReading, segments: segReadings)
}
```

### 4. `enterSegmentMode()` で境界を参照

AzooKey の `segmentize()` を呼ぶ前に `fetchBoundaryPref` を確認し、
ヒットすれば保存済み境界でセグメントを構築する。

```swift
mutating func enterSegmentMode() -> CandidateAction {
    if !state.pendingRomaji.isEmpty {
        state.composedHiragana += RomajiConverter.forceFinalize(state.pendingRomaji)
        state.pendingRomaji = ""
    }
    let fullReading = state.composedHiragana

    // 境界学習を優先参照
    if let storedSegments = db.fetchBoundaryPref(fullReading: fullReading) {
        let rawSegments = storedSegments.map { reading in
            let dictCandidates = azooKeyConverter.candidatesForSegment(reading: reading)
            return (reading: reading, candidates: dictCandidates)
        }
        // rawSegments が1件以下になることはないが念のためフォールスルー
        if rawSegments.count >= 2 {
            var segments: [Segment] = []
            var prevText: String? = lastCommittedOutput
            for raw in rawSegments {
                let seg = buildSegmentCandidates(reading: raw.reading, dictCandidates: raw.candidates, prev: prevText)
                segments.append(seg)
                prevText = seg.selectedText
            }
            state.segmentState = SegmentState(segments: segments, focusedIndex: 0)
            return makeCandidateActionForFocusedSegment()
        }
    }

    // フォールバック: AzooKey の分割を使う（既存ロジック）
    let rawSegments = azooKeyConverter.segmentize(fullReading)
    guard rawSegments.count >= 2 else {
        return buildCandidateList()
    }

```

## テスト

`Tests/InputHandlerSegmentTests.swift` に追加:

1. **保存テスト**: `isManuallyAdjusted` セグメントを含むセグメント確定後、
   `db.fetchBoundaryPref(fullReading:)` が正しいセグメント配列を返すこと
2. **再現テスト**: 境界調整確定後、同じ読みで `enterSegmentMode()` を呼ぶと
   `segmentState.segments.map { $0.reading }` が保存済み境界と一致すること
3. **非保存テスト**: 手動調整なし（デフォルト境界のまま）で確定しても
   `boundary_pref` に保存されないこと
4. **フォールバックテスト**: `fetchBoundaryPref` が空の読みに対して `nil` を返し、
   `enterSegmentMode()` が AzooKey の分割にフォールバックすること

## 考慮事項

- **境界マッチは完全一致のみ**: 「きょうはよいてんきです」を学習しても
  「きょうはてんきです」を打ったときには適用されない。部分一致は複雑になるため MVP では対象外。
- **古い boundary_pref のGC**: `performGCIfNeeded()` の対象に `boundary_pref` を追加する。
  条件は `used_at < cutoff`（180日未使用で削除）。`count` カラムがないため単純な `used_at` 比較。
  ```swift
  execute("DELETE FROM boundary_pref WHERE used_at < ?") { sqlite3_bind_int64($0, 1, cutoff) }
  ```
- **上書きポリシー**: 同じ `full_reading` で境界を再調整して確定すると上書きされる
  （`ON CONFLICT ... DO UPDATE`）。最後に確定した境界を優先するのが自然。
- **`azooKeyConverter.candidatesForSegment(reading:)` はすでに `InputHandler+SegmentMode.swift` で
  使用済み**（`resizeFocusedSegment` 内）なので新規 API 呼び出しではない。
