# PLAN260528b: 変換履歴フレーズ記録

## 背景

現在の `recordPrefixes` はセグメント単位でフル読みを記録する。
「東京都」「知事が」を連続確定しても「東京都知事」は履歴に入らないため、
次回「とうきょうとちじ」と入力しても一発で出てこない。

## 目的

複数セグメントの連続確定をフレーズとして記録し、長い固有名詞・慣用句の再利用性を高める。

## 設計案

### Phase 1: 同一セッション内（シンプル）

`doConfirmSegments` が複数セグメントを一括確定するとき、各セグメントを結合した
フレーズ全体も追加で記録する。

```
セグメント: ["東京都", "知事が"]
読み:       ["とうきょうと", "ちじが"]
→ 追加記録: reading="とうきょうとちじ", output="東京都知事"（末尾助詞トリム適用）
```

実装箇所: `InputHandler+Segments.swift` の `doConfirmSegments` 付近。
個別セグメントの `recordPrefixes` 呼び出しに加えて、結合フレーズを記録する。

### Phase 2: セッションをまたぐ（複雑）

連続した別組成の確定を結合してフレーズ記録する。
タイムウィンドウや直前確定との文字列結合判定が必要で実装複雑度が高い。
Phase 1 の効果を見てから判断する。

## 懸念

- フレーズが長すぎる場合（5セグメント以上など）のノイズ増加
- 同一セッション内でも意味的に連続しない確定の結合（「東京都」「出身の」「田中さんが」 → 「東京都出身の田中さん」は記録する価値があるかは微妙）
- フレーズ記録が増えると `fetchHistoryScoredMerged` の LIKE 検索ヒット数が増加し、候補の絞り込み精度が下がる可能性

## 着手条件

- Phase 1 のみ実装する
- フレーズ長の上限（例: 結合後 20 文字以内）を設けてノイズを抑制する
- 既存のセグメント単位記録と二重記録になるが、重複は許容する（スコア集計は SUM 禁止の既存ルールに従う）
