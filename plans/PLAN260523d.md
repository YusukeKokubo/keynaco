# IME 入力機能の簡素化計画

作成: 2026-05-23

## 背景

[`PLAN260523c.md`](PLAN260523c.md) で IME 機能を棚卸しし、入力パイプライン（キー → 組成 → 候補 → 確定 → 次語予測）に限定して削除候補を洗い出した。

本計画は **IME 入力機能のみ** を対象とする。設定画面・履歴メンテ・デバッグ UI・確定後通知系はスコープ外。

## スコープ外（本計画では触らない）

| 対象 | 理由 |
|------|------|
| `generateDateTimeCandidates` | **削除不要**（ユーザー判断。AzooKey では出しにくい日時フォーマットを提供） |
| `LLMCleanser` / CleanserSheet | 設定・履歴メンテ |
| `LLMMisconversionChecker` | 確定後スキャン（入力パイプライン外） |
| EventViewer / IMESandbox | デバッグ UI |
| `LLMPOSClassifier` | Successor の noun-bigram 学習根幹。削除は hard |
| Successor 本体（bigram / 助詞 / `expandSuccessorPrefixes` / pending 先読み） | sandbox で削除不可確認済み（`PLAN260523c`） |
| セグメントモード / Bracket モード本体 / z シーケンス | 同上 |

### Step 3: ~~低スコア履歴（`lowHistory`）の廃止~~ ✅ 完了（2026-05-23, `8a08ae1`）

#### 現状

`fetchHistoryScoredMerged` の結果を `historyRecencyScoreCutoff`（0.5）で二分割:

| 区分 | 配置 | Shift+Delete |
|------|------|--------------|
| `highHistory` | AzooKey より前（最大 3 件） | 可（`historyEnd` 内） |
| `lowHistory` | AzooKey・カタカナの後ろ | **不可**（`historyEnd` 外） |

候補リスト組み立て・`initialRow` 判定・`CandidateLayout` が複雑化している一方、低スコア行は削除もできず、リストを膨らますだけの可能性が高い。

#### 変更方針

**閾値以上の履歴のみ表示**し、閾値未満は候補に載せない（DB からは削除しない。学習データとして残る）。

| 操作 | ファイル |
|------|----------|
| 簡素化 | `InputHandler+Candidates.swift` — `CandidateListSources.lowHistory` 削除、閾値未満行は候補に載せない（DB 記録は維持） |
| 同上 | `collectCandidateSources` — high/low 分割を high のみに。`totalHistoryCount` は **表示対象の high 件数** に合わせて見直す（低スコアのみ DB にある読みで autoShow が誤って履歴あり扱いにならないよう注意） |
| 同上 | `assembleCandidateList` — `hiraganaInHistory` / `katakanaInHistory` から `sources.lowHistory.contains` 参照を削除 |
| 同上 | `buildSections` — `.lowHistory` セクションと `preLowLayout` 重複排除ブロックを削除 |
| **`historyEnd` 関連** | `CandidateLayout` の `historyEnd` は **もともと `.highHistory` セクション末尾**（`.lowHistory` は `historyEnd` 外）。lowHistory 除去後も `layout.historyEnd` の定義自体は変わらないが、上記 `hiraganaInHistory` / `totalHistoryCount` / 候補件数の変更で **返る `historyEnd` 値とテスト期待値がずれる** ため、`InputHandler+Candidates.swift` と `InputHandlerCandidatesTests`（`testSnap_A4_*` / `A5_*` 等）をセットで更新すること |
| 簡素化 | `CandidateLayout.swift` — `CandidateSection.Kind.lowHistory` と `defaultSectionOrder` / `zenzaiFirstSectionOrder` から `.lowHistory` 削除 |
| テスト更新 | `InputHandlerCandidatesTests.swift` — lowHistory 関連アサート削除・期待値更新 |
| テスト更新 | `CandidateLayoutTests.swift` — `.lowHistory` ケース削除 |

#### ドキュメント

- `docs/domain/architecture.md` — 候補優先順位から「低スコア履歴（AzooKey 後）」行を削除
- `docs/domain/glossary.md` — `historyEnd` 説明から lowHistory 言及を削除

#### 検証

- 閾値未満の履歴のみ存在する読み → 低スコア行は候補に出ず、AzooKey のみ（`testSnap_A4_LowHistoryOnly` 相当）
- 高スコア履歴 + AzooKey の並び・Shift+Delete 境界（`historyEnd` = highHistory 末尾）が従来どおり
- `testSnap_A5_HighAndLowHistory` 等: 候補末尾の低スコア行が消え、`historyEnd` は高スコア分のみのまま

#### リスク

**低〜中** — 古い・低頻度の変換を AzooKey 後ろから拾っていたユーザーには後退。ただし Shift+Delete 不可だったため実用性は限定的。

sandbox で「スコア 0.5 未満の履歴だけがヒットする読み」を 1 ケース試し、削除前後の候補 diff を記録しておく。

### Step 4: Bracket モード `bracketOptions` の間引き（優先度：中）

#### 現状

Bracket モード本体は差別化機能として **維持**（`PLAN260523c`）。一方 `bracketOptions` に日本語入力中ほぼ使わない記号が多数定義されている。

#### 残すキー（案）

日本語文書で Bracket 候補として意味があるもの:

```
[ ] ( ) { } ? ! / . ,
```

#### 削除するキー（案）

ASCII モードや直接入力で足りる記号:

```
@ # $ % ^ & * < > _ + | : "
```

#### 変更

| 操作 | ファイル |
|------|----------|
| マップ縮小 | `InputHandler+BracketMode.swift` — `bracketOptions` から上記キーを削除 |
| テスト確認 | `InputHandlerPunctuationTests.swift` — 削除キー専用テストがあれば削除 |

#### ドキュメント

- `docs/domain/architecture.md` — `bracketOptions` の例示を残すキーに合わせて更新

#### 検証

- 残すキー（`[` `(` `?` `/` `.` `,` 等）: 組成空・非 ASCII モードで押すと **従来どおり Bracket モードに入り**、候補表示・Enter/Escape・Shift+Delete が動くこと
- 間引いたキー（`@` `#` 等）: **`bracketOptions` から候補行が消えるだけ**。例: `[` で Bracket モードに入ったとき、候補リストに `@` / `＠` が **現れなくなる** こと（`@` キー単体のトリガー挙動は変わらない — `@` は Bracket トリガーキーではない）

#### リスク

**低** — 削除キーは `@` 等を Bracket 経由で全角化していた上級者向けショートカットのみ失う。必要なら ASCII モードで入力可能。
