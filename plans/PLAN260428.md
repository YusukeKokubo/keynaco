# PLAN260428: コードベース リファクタリング計画

## Context

機能追加が続いた結果、以下の技術的負債が蓄積している。バグを仕込まずに安全に進めるため、リスク別に4フェーズに分けて実施した。

---

## フェーズ 1: デッドコード・マジックナンバー除去（完了 `a2d7c9d`）

- `Sources/InputSource.png` 削除（.tiff のみ参照）
- `buildSegmentAttributedString` の重複を `SegmentState.attributedString()` に統合
- 未使用の `logger` / `import os` を `InputController.swift` から削除
- `KeyCode` を internal に昇格し `capsLock: 57` を追加

---

## フェーズ 2: SQLite クエリパターンの共通化（完了 `35b85be`）

`Sources/DatabaseManager.swift` の `sqlite3_prepare_v2` + `defer sqlite3_finalize` + `sqlite3_step` パターン（16回以上）を private ヘルパー2つに集約。

- `queryStrings(_:bindings:columnIndex:) -> [String]` — SELECT 系
- `execute(_:bindings:)` — INSERT / DELETE 系

`recordHistory` / `recordBigram` は `sqlite3_last_insert_rowid` / `sqlite3_changes` を使うため手動のまま。

---

## フェーズ 3: `handle()` の責務分割（完了 `df6afba`）

`Sources/InputHandler.swift` の `handle()`（約200行）をディスパッチャに縮小し、責務ごとに3メソッドに切り出した。

| メソッド | 内容 |
|---------|------|
| `handleSuccessorMode(...)` | Successor モードのキー処理 |
| `handleCandidateVisible(...)` | 候補ウィンドウ表示中のキー処理 |
| `handleNormalInput(...)` | 通常文字・スペース・句読点の入力処理 |

---

## フェーズ 4: 変数名・関数名の整理（完了 `bf3760d`）

`do` プレフィックス（ObjC 由来）の除去と `ss` ローカル変数名の統一。

| 変更前 | 変更後 |
|--------|--------|
| `doRefreshCandidates` | `buildCandidateList` |
| `doCommit` | `commitText` |
| `doEnterSegmentMode` | `enterSegmentMode` |
| `doSuggestSuccessors` | `suggestSuccessors` |
| `ss` (ローカル変数) | `segmentState` |

---

## 見送り（現時点では採用しない）

- **InputHandler の複数ファイル分割**: 1ファイルで全状態遷移を把握できることが IME デバッグ時に有利。
- **BaseTableViewController の共通化**: BigramViewController / HistoryViewController の重複は量が少なく、共通化でかえって複雑になる。
- **純粋関数への分離**: `handle()` を副作用なしの純粋関数に分離するアーキテクチャは正しいが、改修コストが大きいため当面は見送り。
